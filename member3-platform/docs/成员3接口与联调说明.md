# 成员3接口与联调说明

## 运行模式

系统支持**链下/链上双模**（`web3.enabled` 开关），已对接成员1的
`RWA_Core_Asset.sol`（ERC-3525，仓库：merlin746/supply-chain-rwa-platform）：

- **链下存证模式**：全流程落 MySQL，`tx_hash` 以 `OFFCHAIN-` 前缀占位，无需链节点即可演示。
- **链上模式**：
  - 凭证开立 → `mintRWAAsset(to, slot, value, maturityDate, contractHash, uri)`（核心企业私钥签名）
  - 凭证拆分 → `transferFrom(fromTokenId, to, value)`（持有方私钥签名，合约铸造继承 Slot 的子凭证）
  - 到期兑付 → `settleAsset(tokenId)`（银行私钥；合约要求已到期，失败显式报错不回退）
  - 银行核验 → 追加 `balanceOf` / `ownerOf` 链上交叉校验，比对链上余额与业务库
  - 事件同步 → 每 10 秒解码链上事件回写业务库（见下）

约定：
- 金额单位：链上 uint256 为「分」，库中为「元」（×100，`ChainTxService.toCents/toYuan`）
- 私钥托管：`web3.keys.<企业ID>`，平台代各企业签名；本地演示预置 Hardhat 账户 #1~#5 公开私钥
- 链上交易失败明确返回错误；链上模式要求配置正确的企业密钥，不再静默生成链下凭证。

## 已对接的链上事件（成员1合约）

| 事件 | 处理 |
| --- | --- |
| AssetCreated(tokenId, issuer, slot, faceValue, maturityDate, contractHash, metadataURI) | 补缺入库，ownerOf 反查持有方映射企业 |
| AssetSplit(parentTokenId, childTokenId, value) | value 非 indexed，从 data word0 读取；补缺（后端自身拆分已落库则跳过，幂等） |
| AssetStatusChanged(tokenId, old, new) | 1→FROZEN 2→REVOKED 3→SETTLED（0 Active 不覆盖业务状态） |
| AssetSettled(tokenId, amount) | 凭证 → SETTLED |
| AssetRevoked(tokenId, revokedBy, reason) | 凭证 → REVOKED |
| TransferValue / Transfer / RoleGranted 等 | 原始日志存入 blockchain_event，不改业务表 |

### RWA 凭证
- GET /api/token/list?enterpriseId=&status=&ownerAddress=
- GET /api/token/{tokenId}

### 融资
- GET /api/loan/list?status=&supplierId=&bankId= — 强制按当前供应商或银行过滤
- POST /api/loan/apply
- PUT /api/loan/{id}/approve — 审批通过，凭证转 PLEDGED
- PUT /api/loan/{id}/disburse — 一键放款，凭证保持 PLEDGED
- PUT /api/loan/{id}/settle — 到期兑付（需凭证已到期），链上调用 settleAsset，凭证转 SETTLED
- PUT /api/loan/{id}/reject

## 凭证状态机

```
UNCIRCULATED --拆分/转让--> CIRCULATING --融资审批--> PLEDGED --到期兑付(settle)--> SETTLED
                                                             \-- 链上 Frozen/Revoked --> FROZEN/REVOKED
```

放款（disburse）不改变凭证状态——放款只是资金划转，质押在到期兑付时才解除，
与链上合约状态机（Active → Settled 要求 block.timestamp >= maturityDate）一致。

拆分守恒约束：子凭证金额 + 父凭证剩余金额 == 拆分前父凭证金额；
子凭证继承父凭证 Slot（到期日）与核心企业信用背书（metadata）。

## 安全边界与已知限制（比赛 Demo 工程）

1. **服务端鉴权**：Bearer 会话认证、角色操作授权及企业数据隔离已执行；前端路由仅展示
   当前角色工作台。会话使用内存存储，适用于本地单实例 Demo，重启后需重新登录。
2. **密钥管理**：数据库密码经环境变量 `DB_PASSWORD` 注入（默认值为占位符）；
   企业托管私钥放在不入库的 `backend/application-local.yml`（模板见 application-local.yml.example），
   真实私钥禁止提交仓库。
3. **链上/库内一致性**：链上模式为「先发交易、后写库」，链上成功而本地回滚时
   由事件同步的补缺机制（AssetCreated/AssetSplit 回填）兜底对账，链上数据为准；
   更强保证需引入 outbox 模式。
4. **事件去重**：以 tx_hash + log_index 为唯一键，同一交易内多个同类型事件不会丢失。
   每条事件的保存与业务投影使用同一事务，失败时对应事件回滚并保留扫描位置；
   重试时已完成的事件会按去重键跳过。
5. **业务质押与资金**：融资审批中的 PLEDGED 是业务库流转锁；当前后端尚未调用
   RWA_Settlement 的 NFT 托管接口。放款与兑付记录为演示状态操作，不调用真实银行资金系统。

## 为什么先保存 blockchain_event

成员1/2合约如果最终 ABI 还没固定，后端不应该自行猜测事件参数。
因此第一阶段：
- topic0
- topics
- data
- txHash
- blockNumber
- contractAddress

全部保留。

ABI 固定后再做精确参数解码，写入 rwa_token / loan_application。

这样可以避免因为合约最终修改导致数据库脏数据。

## 数据库导入注意（Windows）

MySQL 命令行客户端默认按 GBK 解释脚本，导入中文种子数据会报
`ERROR 1406 Data too long`。请加字符集参数：

```bash
mysql --default-character-set=utf8mb4 -uroot -p < database/rwa_supply_chain.sql
```
